# 本机 Codex 接入方案（暂缓开发，备查）

2026-10-08。

**状态：仅记录方案，尚未实现。** 当前版本先推送 GitHub；接入 Codex 的开发等维护者有空、明确启动时再进行。本文件不是已有功能的使用说明，也不意味着已经打包或发布新版本。

## 目标与结论

在开源桌面版中增加一个可选的本机 Codex 后端，让用户利用自己电脑已有的 Codex 登录与配置，进行普通对话，以及围绕某个待办的独立长期对话。

现有 OpenAI 兼容 API 后端、多个普通对话、业务数据、附件处理及页面生成能力保留。没有安装或登录 Codex 的用户仍可使用原来的方式。

技术上可行。已有本地原型验证过独立会话、重启续聊、附件读取与任务修改，但那套实现和本仓库的数据模型、工具、桌面运行方式有差异，不能直接覆盖。此方案基于静态代码评估；本仓库的移植效果尚未验证。

## 连接方式

```text
浏览器 / Electron 窗口
  → Next 聊天接口
  → 本机对话后台与任务队列
  → 独立 stdio codex app-server
  → 平台提供的业务工具
  → 同一份业务数据库和附件目录
```

- 后台由用户本机运行，使用该运行用户已有的 Codex 凭据和配置，不读取、复制或打包开发者的登录文件。
- 通过 initialize / initialized 建立协议连接，thread/start 创建独立会话，保存 threadId；重启后通过 thread/resume 恢复。
- 不恢复或续写 Codex 桌面正在使用的活跃 thread。共用登录不代表共用当前桌面聊天上下文，也不自动继承桌面的全部技能、插件或工具。
- 手机沿用现有配对网关访问桌面应用，AI 实际在电脑后台运行；电脑关闭时不能继续处理。
- 普通对话可以查询全平台业务数据；任务会话每轮重新读取本任务最新要求、进展、直接关联资料与附件。历史聊天不能代替最新业务状态。

## 与当前架构的适配

### 1. 增加后端选择和连接诊断

在现有模型设置中增加“本机 Codex”选项，保留 API 配置。检测可执行文件、登录状态、兼容版本、实际可用模型和推理档位；支持用户指定路径，给出未安装、未登录、登录失效、额度不足和后台退出的明确提示。

尽量让一段对话固定使用同一后端；切换后端时开启新的对话，或设计明确的历史导入流程，不静默丢弃记忆。Codex 可能使用 ChatGPT 登录或 API 配置，界面应说明实际运行方式和用量归属，不能一概宣称免费。

### 2. 保留 Conversation，增加会话映射

本仓库已有 Conversation、Message、ChatSummary 和按对话压缩上下文的机制。已有原型则按一个 general 范围与 task:<id> 范围保存 ChatSession，不应原样搬来压缩掉现有多对话能力。

实施时沿用 Conversation，增加后端标识、Codex thread 映射及可选任务关联；具体字段与关系在开发时确定。每个任务默认有自己的长期会话，普通对话与任务会话独立。

补充 ChatTurn / ChatToolRun 或等价结构，保存客户端请求键、运行状态、消息关系和工具审计。旧 API 对话和摘要保留，数据库里有 Message/modelJson 不代表 Codex 已经拥有对应历史。

桌面老用户需要在 src/lib/schema-upgrade.ts 增加自动升级步骤，不能要求安装者手动运行 Prisma CLI；新安装的模板库同步更新。变更前按实际运行环境执行备份。

### 3. 复用业务工具，加入任务范围限制

把现有 agent-tools、data-tools、page-tools 中的业务处理抽成可复用函数，分别适配 AI SDK 与 Codex dynamicTools，减少两套后端长期各自增长的业务逻辑。

保留参数校验、金额与日期口径、业务事务及附件归档。模型只通过明确提供的工具操作平台；不因接入 Codex 默认开放终端、源码编辑、外部发送或插件执行。

任务会话的访问与修改范围必须由服务端工具检查：默认修改当前任务，创建子待办时关联当前任务，直接关联资料可读取；不只依赖提示词。Task.detail 保留最初要求，新要求或业务变更写成进展。

现有工具使用 Next revalidatePath，独立 Node 后台不能直接原样调用，需要分开处理数据库操作与 Next 页面刷新。工具修改与执行结果在同一事务中落库，用调用编号去重；读取工具允许安全重试。

### 4. 保留后台处理与前端体验

复用后台队列、排队/思考/回复状态、发送去重、重启后恢复和失败记录机制。页面刷新或关闭不会中断已接收的请求，但整台应用退出或后台重启仍须正确处理运行中轮次。

前端当前使用 AI SDK useChat 和 UIMessage 流，Codex 返回的是协议事件。实施时统一前端事件格式，或提供清楚的后端适配组件，保留回复、工具状态、警告与页面制作进度。

任务详情增加聊天入口与弹窗，桌面并排显示任务资料、手机可查看要求及进展；完成或关闭时刷新业务数据。同页重开保留草稿，避免跳走后丢失当前任务和浏览位置。

后台异常后不能自动重放可能已写入的请求；重复发送同一 requestKey 返回原结果。先用单后台串行处理业务修改，再根据实际需求评估并发。

### 5. 网页制作必须独立适配

当前版本的页面能力包括独立模型调用、设计规范、高推理、流式进度、pageStore 持久存储、schema 声明、版本恢复、全屏和下载。这些都应保留。

已有本地 Codex 原型的通用聊天使用 low 推理，工具未包含本仓库的完整页面生成、页面数据读写、账单与体检导入。因此直接替换聊天后端会丢功能。

可分两步：

1. 首阶段保留现有 API 页面生成服务，Codex 对话调用该服务。需要原 API 配置时在界面清楚提示，并说明费用仍计入该 API；不能把它表述为完全由 Codex 生成。
2. 再增加 Codex 独立页面生成调用，仍然传入明确需求、真实数据、旧页面和存储格式，按模型实际支持选择较高推理档位。不能照搬百炼/DeepSeek 的 reasoningEffort: max 或固定 token 上限。

页面生成完成后沿用现有 HTML 提取、校验、版本保存和沙箱展示。高推理生成可能较慢，轮次与工具超时、取消、进度显示必须一起适配，不能机械照搬原型的三分钟上限。

### 6. 桌面生命周期与附件处理

由 Electron 管理后台启动、退出、日志、可用端口和工作目录，与现有 Next 子进程一起收尾，避免退出后留下孤儿进程。后台只绑定回环地址，使用内部令牌；浏览器经过 Next 和现有配对/认证入口访问。

复用安装版和绿色版各自的数据目录，不固定为源码仓库 data 路径；端口不能与同一电脑上其他应用冲突。用户姓名、界面语言和时区沿用现有设置。

优先复用当前 Node 文件处理能力，避免依赖某台开发电脑的 Codex 内置 Python 路径或 skills 目录。保留图片、PDF、DOCX、XLSX 和文本支持；需要新增运行时依赖时另行确认分发方式。保留原件和重新读取的受限工具，不能仅凭文件名假装看过附件。

打包检查不得带入私人数据库、上传文件、Codex 认证、会话历史或密钥。接入代码完成后不自动生成桌面包，打包与 Release 发布等明确要求再执行。

## 本地版与公网版的边界

桌面版使用安装者本机的 Codex。公网部署中的后台运行在服务器上，不能自动连接访客电脑上的 Codex 登录，也不能共用开发者账号为所有访客提供服务。

2026-10-08 核对官方文档：本地或开源应用可继续使用 app-server 认证，官方建议迁移至 Sign in with ChatGPT；商业或托管服务不允许使用 app-server 认证方式。因此公网或商业产品的用户认证、用量归属与授权需要单独设计，不能把本机方案直接用于托管服务。实施时重新核对当时的官方要求。

dynamicTools 和工具回调目前标为实验性接口，必须记录验证过的 Codex 版本，并对版本不兼容提供提示。此方案不保证未来协议和能力不变。

来源：[OpenAI 官方文档：Codex App Server](https://learn.chatgpt.com/docs/app-server)，会话生命周期、动态工具与 Auth endpoints。

## 开发顺序与验收

1. 本机 Codex 可选后端：连接诊断、独立普通会话、两轮连续记忆、后台重启续聊、登录和额度错误提示。
2. 任务会话：最新任务上下文、弹窗体验、修改本任务、保留 detail、跨任务拒绝、重复提交不重复写。
3. 功能补齐：原有工具、附件格式、网页生成与存储，验证 API 模式仍可正常使用。
4. 桌面适配：安装版/绿色版的数据路径、手机配对访问、退出清理、后台异常恢复、旧数据库升级。
5. 完成对应类型检查、构建及必要的真实模型验收后提交并普通推送；明确要求分发时才打包和发布。

本文件只保存未来开发的起点。恢复工作时先核对仓库最新状态、官方协议和用户当时的范围，不把方案里的步骤当作自动执行授权。
