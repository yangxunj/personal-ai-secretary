# 专题插件架构（内置试点）

目标是把某个专题的专用规则、界面、操作说明和平台适配放在一起，让主程序处理通用导航、模型和数据能力。当前首先把「周末去哪」整理为一个内置插件，安卓试点使用；网页和 Windows 暂未接入该插件的运行入口。

## 目录与职责

`src/topic-plugins/hk-weekend/` 是插件目录：

- `PLUGIN.md`：用途、能力和数据说明，类似 skill 的入口文档。
- `index.mjs`：标识、路由、名称、能力声明和页面挂载入口。
- `engine.mjs`、`service.mjs`、`recommend.mjs`：活动解析、查询编排与 AI 推荐规则。
- `panel.mjs`、`styles.css`：专题页面；页面使用传入的能力，不直接访问安卓桥接。
- `android-adapter.mjs`、`android/`：安卓能力适配和原生限定来源的网络实现。

`src/topic-plugins/registry.mjs` 是受审内置插件的注册清单，校验标识与路由不能重复；安卓主程序根据注册清单生成专题卡片、路由和页面。`experiments/android-shared/web/topic-plugin-adapters.mjs` 和安卓 `TopicNativeRegistry` 是平台的能力装配点。增加插件时，除了插件目录，还需在这几个明确的注册处接线、提供相应平台适配并重新构建；不是把任意文件复制进去就能自动安装。

## 安全与平台边界

目前插件随应用源码审核、编译和打包，安卓与 Windows 的更新需要重新构建安装包；没有在线下载、热加载或第三方插件市场。插件代码与应用在同一运行环境中，能力清单只用于检查接线是否齐全，**不构成独立沙箱或细粒度授权机制**。不能将不可信插件直接加入应用。

周末插件继续使用之前的安卓缓存位置，升级不要求清空旧数据；该结论仍需设备覆盖安装确认。模型密钥由现有原生通道保管，活动查询走该插件限定的官方来源；未声明或未注册的安卓插件不会获得对应原生处理器。其他专题、用户自装插件、插件权限管理和不同设备间数据同步都不在本次试点范围内。

## 检查

运行 `experiments/android-shared/build.ps1` 可构建并检查依赖边界、插件注册、周末查询和推荐规则。插件源文件及其哈希记录在 Android 构建清单中。合成测试与构建不等于手机实测：覆盖升级、旧缓存、联网来源和真实 AI 推荐仍需在设备上确认。
