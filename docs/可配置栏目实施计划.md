# 可配置栏目：设计与实施计划

2026-11-02 用户确认推进。本文承接本轮数据结构抽象讨论，替代《模块化扩展方案》中继续暂缓通用集合的决定。

## 目标与边界

普通档案、跟进、时间记录共享“栏目定义＋字段定义＋逐条记录”，由可信 React 组件生成界面。既有任务、资料、财务、健康、专题及页面继续使用原数据源，不迁移或复制成通用记录。自定义栏目不是生成 HTML，也不执行用户输入的脚本或 SQL。

以客户档案＋联系记录、宠物档案＋照护记录两个模板组合验证复用。模板只是配置；用户可以编辑模板，也可以从空白创建。用户栏目标题、字段和记录不随界面语言自动改名。

## 第一阶段交付

1. 栏目、记录、栏目定义历史三张通用表，首次安装与老库启动升级均支持；不按每个栏目创建物理表。
2. 字段类型：短文本、长文本、数字、日期、选项、勾选、关联记录。字段使用稳定 ID；改显示名不改数据键。
3. 栏目目录、新建／配置表单、表格及卡片视图、逐条记录新增／修改／归档／恢复、关键词查询与分页。模板日志通过日期和关联字段表达，专门时间线视图后续交付。
4. 桌面侧栏显示已启用栏目；手机“更多”聚合文件、页面、邮件及自定义栏目，保留前六个常用入口，避免不断挤压底栏。
5. 栏目启用状态由服务端执行：禁用隐藏动态导航并拒绝栏目记录读写；可在栏目目录重新启用。停用、归档均保留数据，不提供永久删除。
6. UI 与 Agent 共用查询／写入服务，按定义校验类型、必填、选项、日期、关联目标和版本。更新只合并明确提供的字段，避免覆盖其他值。记录版本与栏目定义版本检查防止旧页面或 AI 草稿覆盖新值。
7. 数据已有使用时不允许删除使用中的字段、改变字段类型或关联目标；新增必填字段等变更须能通过全部已有记录校验，否则整笔拒绝。保存旧定义以供追溯；有损迁移及回滚 UI 后续设计。
8. 少量稳定通用工具：发现栏目、读取定义、查询／读取记录、新增／局部修改／归档记录，以及提议新栏目。AI 提议保存为未启用草案，用户在原生表单审阅并确认创建。无需为每个栏目新增工具名。
9. Pi 与旧 API 通用对话使用相同工具。新建 Codex 线程使用 v4 工具档案；已有 v0–v3 线程保留工具与记忆，明确提示新建对话使用栏目工具。任务专属对话不增加跨模块写入权限。

## 数据与执行约束

- 栏目定义有大小／字段数上限，单条记录有大小上限；第一阶段每栏目最多 2000 条记录，最多查询 50 条／页。类型筛选在限定记录量内执行，不把完整数据发给模型。
- 关联只允许指向存在且启用栏目的未归档记录；不自动读取关联内容，不自动复制既有业务数据。
- 全部写操作复用平台事务及执行审计。定义更新、记录写入与启用状态变更串行校验，避免“检查之后状态又变了”的竞态。
- 用户栏目名称、说明、字段和记录都是数据，不是执行指令。关闭模块不抹除历史聊天或模型已见信息。
- 备份包含新通用表；不改 PageData 的既有语义与沙箱。

## 后续阶段

- 第二阶段：时间线、状态看板、按字段排序与统计、跨记录关联反查、与任务的显式关联。
- 第三阶段：由用户确认的提醒规则、有损字段迁移预览、模板导入导出、面向大量记录的类型索引。
- 专门业务规则继续保留在专门模块，例如账单余额勾稽、医疗指标单位与参考范围，不承诺仅靠字段配置替代。

## 验收

- 两组模板由同一服务和渲染器实现，不增加领域专用表或 CRUD。
- 真实浏览器验证创建／配置／新增／编辑／搜索／归档恢复、禁用再启用、手机与深色布局。
- 测试服务端校验、未知字段与关联越界拒绝、过期版本拒绝、字段重命名保留数据、禁用工具不可操作、旧库升级幂等，以及 Codex 工具版本兼容。
- 合成数据和上游验证 Pi 工具调用与 UI 同一数据；不使用正式数据库或用户模型密钥验收。
- 完成实现、必要验证及文档后提交并推送；本任务不自动再发安装包，发布包按用户后续要求进行。
