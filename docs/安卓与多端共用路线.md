# 安卓与多端共用路线

日期：2026-11-03。状态：M0/M1 完成；前两版本地/升级验收通过，第三版真实 DeepSeek 与 AI 新增书单已获用户确认。M2 继续：第四版共用正式待办工具与策略，任务创建/查询/完成已实现并交付，设备验收待回；完整会话与产品 UI 尚未完成。

## 产品目标

在同一开源仓库维护网页、Windows、安卓三个版本。安卓平板在电脑关闭、没有自建服务器时也能使用；数据库、附件与会话保存在平板。AI 首版使用用户配置的云端 API，独立运行不代表离线推理。

新增或修正通用业务逻辑时修改同一份源码，各端重新构建后获得更新。平台特有能力通过适配层提供，避免复制一套安卓业务实现。构建新的安装包与向用户发布是两个步骤；本任务可制作开发测试包，正式发布、商店上架、生产部署另行处理。

## 已确认的现状

- 当前源码基线：`5657662`，版本 `0.6.0-beta.4`。Windows 使用 Electron 38 启动本地 Next.js 15 standalone 服务，再打开本地窗口；网页和桌面已共用主应用。
- `src/app` 中有服务端页面、Server Actions 和 API 路由，不能作为静态网站直接整体装进 WebView。
- 数据层为 Prisma 6 + SQLite；附件和 Pi 会话使用 Node 文件系统；Pi 运行层依赖 Node。SQLite 文件格式可复用不等于 Prisma 运行时可在安卓直接使用。
- `sharp`、`@napi-rs/canvas` 涉及原生二进制；扫描 PDF、图片处理要单独验证。Gmail 桌面实现调用 Windows `gws.exe`。
- 本机 Codex 集成依赖外部进程与本机登录，不作为安卓首版必备能力。

这些是源码检查结果，不代表已构建安卓包或完成实机验证。

## 架构约束

目标依赖方向：界面/AI 工具入口 → 共享应用服务 → 领域规则与平台接口；平台适配器实现接口。领域规则不能反向导入 Next.js、Electron、安卓桥接、Prisma 或 Node 文件系统。

| 层次 | 共用内容 | 平台差异 |
| --- | --- | --- |
| 领域规则 | 字段校验、状态规则、工具参数、数据结构、提示词 | 无系统 API |
| 应用服务 | 查询/写入流程、权限与范围约束、审计和幂等语义 | 注入存储、时钟、ID 等依赖 |
| 界面 | React 组件、交互状态、中英文资源 | 路由、数据调用、平板布局与系统入口 |
| 运行与存储 | 接口、迁移版本和兼容规则 | 服务端/Windows 实现、安卓实现 |
| 系统功能 | 能力声明和统一入口 | 文件、密钥、相机、通知、后台调度、授权 |

先抽取一条实际功能链，再扩展边界；不先搬动整个仓库。共享并不要求所有模块立刻变成独立 npm 包，也不以共享文件数或代码比例作为验收依据。

Server Actions 与 API 路由保留为网页入口，逐步改为调用共享应用服务。安卓不能通过访问电脑服务来假装完成独立运行。界面输入校验不能替代写入端校验；AI 与手工操作必须执行同一业务规则。

| M2 共用逻辑闭环 | 抽取真实业务规则和服务接口，网页/Windows 与安卓接入 | 同一规则修改后两端构建均生效；手工与 AI 写入同一数据；旧端回归通过 |
| M3 首版主要业务 | 聊天、待办、资料、自定义栏目、必要附件、设置和中英文 | 平板日常流程可用；支持取消、错误恢复、键盘和横竖屏；功能能力表明确 |

M1 与 M2 可在同一隔离试验中逐步完成，但必须分别记录运行兼容性与共享逻辑证据。若嵌入后端需要维护脆弱的原生依赖或不可控后台进程，则转向平台适配方案，不长期维护两套正式后端路线。

## 首版范围与后续范围

首版围绕前台使用：API AI 聊天、任务、资料、栏目、图片及基础附件、导入导出与备份。账务、健康、保单、专题及生成页面等现有模块逐项接入，未验证的模块不显示为完整可用；不得丢失专门业务规则。首版是否纳入每项复杂功能由试验后的能力表确定。

Gmail、持续后台扫描、完整扫描 PDF 处理、语音、通知和跨设备自动同步分项推进。Windows 与安卓首版各自拥有本地数据；数据迁移通过明确的导入/恢复进行，不默认自动同步。跨端导入检查 schema 版本和功能兼容性，不允许旧客户端静默覆盖新结构。

## 统一验收原则

1. **独立性**：电脑服务关闭、无远端秘书服务时，安卓能启动、读写和重开数据；云端模型连接单独标注。
2. **源码共用**：从同一提交构建；一次共享规则更新同时影响网页/Windows 和安卓。平台层不重复规则；仅模拟安卓接口不算安卓验收。
3. **数据可靠性**：覆盖升级、进程结束、失败保存、附件重开与备份恢复均用合成数据验证；卸载可能删除应用数据，必须有导出路径。
4. **既有版本**：每轮改造执行对应的既有测试；涉及页面和桌面桥接时做实际浏览器/桌面回归。
5. **真实设备**：模拟器、静态构建和自动测试分别记录；至少一台安卓平板验证后才能宣布平板可用。缺设备时明确待验，不补写成功。
6. **包的边界**：保持仓库打包白名单和密钥剥离约束；只使用合成测试资料，不打包私人仓库、正式数据库、用户凭据或开发机配置。

## 执行与估算

按 M0→M1→M2 的依赖顺序持续推进，每个可独立验证的里程碑检查 diff、提交、普通推送并核实远程；不为每次编辑制造提交。已授权范围内的常规选型和修正自主完成。遇到新权限、收费服务调用或不可替代的设备输入时只说明具体缺口，继续其他独立工作。

此前提出的技术验证 1～2 人周、首版 6～12 人周只是未验证估计。M1 后按实测的依赖兼容性、复用范围和验收设备重新估算，不作为交付承诺。
