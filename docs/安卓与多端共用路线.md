## 产品目标

### 三端共用目标复核

用户再次强调：网页/Windows业务更新后，安卓应通过重新构建获得同样更新。当前还没有完整达到这个目标，不能把“已共用若干规则和组件”描述为“整套产品已经共用”。

- 网页与Windows使用同一Next主应用。安卓仍位于隔离试验目录，具有单独的试验页面、平台接线和简化会话快照流程。
- 已实际共用：栏目校验/写入策略与工具契约、通用待办契约/策略、上下文估算、消息正文、会话列表展示/日期分组、文本输入控件，以及上游Pi工具循环能力。
- 尚未统一：完整产品页面、业务应用服务的调用流程、完整AI会话管理与提示词接线。正式Pi SDK SessionManager与安卓快照管理目前各走自己的存储/生命周期路径；不能保证任意主应用改动都会自动进入安卓。
- 必要的平台差异包括存储、文件、密钥、网络与系统生命周期；但“平台适配”不能成为继续在安卓目录维护另一套业务流程的理由。应逐步将应用流程抽为共同模块，正式入口与安卓入口同时调用，适配器只处理系统能力。

后续优先级调整为先收敛共享应用服务、界面和会话接口，再扩充业务。每个迁移切口都要列明同一源码的实际消费者、平台差异和未统一处，并验证同一次共享变更在三端接线生效；不再以连续增加独立安卓试验功能作为完成目标的替代。

测试也分层执行：共用业务规则由开发者自动回归；平台桥接与产品接线由开发者集成验证；交给用户的手工验收主要覆盖真实设备输入法、触摸、旋转、重开和覆盖升级等环境行为，以及少量端到端确认。重复测试本身不说明代码独立，但不得把可以自动化的整套业务反复转交用户。

### 待办应用服务收敛（2026-11-04）

新增 `src/lib/tasks/service.ts`，把通用待办创建、查询、局部更新、缺失任务处理和 AI 工具结果投影集中到同一应用服务。正式网页/Windows 的 `agent-tools.ts` 和安卓的 `web/tasks.mjs`、`web/pi-runtime.mjs` 已接入；安卓手工待办面板也通过该服务读写。同步桥接和异步 Prisma 执行同一工作流，界面不需要维护两套业务规则。

平台端仍负责实际查询和排序、保存、事务与并发控制。正式服务使用原有 `db` 事务代理，外层审计、取消与持久回执保持原调用链；安卓保留 SQLite `commitTool` 的业务/回执原子写入与 `expectedVersion` 检查。重复调用从回执还原当时的结果，不拿当前记录状态冒充原结果；保存异常向上传递，不返回成功。

验证包括正式工具加隔离 Prisma 数据库与实际安卓 JS 构建产物的行为对照：创建、原文保留、默认未完成筛选、完成后查询、空负责人清除、空日期不覆盖、缺失任务和非法参数；另检查回执重放、存储失败和版本冲突。共享服务纳入平台依赖边界检查和构建源码哈希。网页生产构建使用隔离源码目录和合成配置；不读取正式数据库或模型凭据。

这一步仍不是完整待办模块共用：网页手工表单 Server Actions、带负责人/已读计数等视图的完整列表查询和待办页面尚未迁入，任务专属聊天策略保持原有边界。下一切口先统一正式存储适配与手工创建/状态/负责人操作，再收敛查询接口和完整界面；不把简化工具的默认 20 条限制直接套到正式列表。完整会话管理仍待后续迁移。本轮只做内部构建验证，不覆盖已交付的 0.7.0 APK 文件，也不新增用户整套手工验收要求；原生设备测试未执行。

本轮验证结果：56 项自动检查通过（安卓共享规则 21、消息展示 2、会话/输入控件 3、依赖边界 3、正式平台集成 23、任务专属范围 4）；TypeScript 检查、隔离 Next 生产构建、安卓 `assembleDebug` / `assembleAndroidTest` / `lintDebug --offline` 均通过。测试 APK 只完成编译，没有连接设备执行 instrumentation。JS 构建仍有既有 bundle 体积提示。

在同一开源仓库维护网页、Windows、安卓三个版本。安卓平板在电脑关闭、没有自建服务器时也能使用；数据库、附件与会话保存在平板。AI 首版使用用户配置的云端 API，独立运行不代表离线推理。

新增或修正通用业务逻辑时修改同一份源码，各端重新构建后获得更新。平台特有能力通过适配层提供，避免复制一套安卓业务实现。构建新的安装包与向用户发布是两个步骤；本任务可制作开发测试包，正式发布、商店上架、生产部署另行处理。

## 已确认的现状

- 当前源码基线：`5657662`，版本 `0.6.0-beta.4`。Windows 使用 Electron 38 启动本地 Next.js 15 standalone 服务，再打开本地窗口；网页和桌面已共用主应用。
- `src/app` 中有服务端页面、Server Actions 和 API 路由，不能作为静态网站直接整体装进 WebView。
- 数据层为 Prisma 6 + SQLite；附件和 Pi 会话使用 Node 文件系统；Pi 运行层依赖 Node。SQLite 文件格式可复用不等于 Prisma 运行时可在安卓直接使用。
- `sharp`、`@napi-rs/canvas` 涉及原生二进制；扫描 PDF、图片处理要单独验证。Gmail 桌面实现调用 Windows `gws.exe`。
- 本机 Codex 集成依赖外部进程与本机登录，不作为安卓首版必备能力。

这些是源码检查结果，不代表已构建安卓包或完成实机验证。

## 架构约束

目标依赖方向：界面/AI 工具入口 → 共享应用服务 → 领域规则与平台接口；平台适配器实现接口。领域规则不能反向导入 Next.js、Electron、安卓桥接、Prisma 或 Node 文件系统。

| 层次 | 共用内容 | 平台差异 |
| --- | --- | --- |
| 领域规则 | 字段校验、状态规则、工具参数、数据结构、提示词 | 无系统 API |
| 应用服务 | 查询/写入流程、权限与范围约束、审计和幂等语义 | 注入存储、时钟、ID 等依赖 |
| 界面 | React 组件、交互状态、中英文资源 | 路由、数据调用、平板布局与系统入口 |
| 运行与存储 | 接口、迁移版本和兼容规则 | 服务端/Windows 实现、安卓实现 |
| 系统功能 | 能力声明和统一入口 | 文件、密钥、相机、通知、后台调度、授权 |

先抽取一条实际功能链，再扩展边界；不先搬动整个仓库。共享并不要求所有模块立刻变成独立 npm 包，也不以共享文件数或代码比例作为验收依据。

Server Actions 与 API 路由保留为网页入口，逐步改为调用共享应用服务。安卓不能通过访问电脑服务来假装完成独立运行。界面输入校验不能替代写入端校验；AI 与手工操作必须执行同一业务规则。

## 首版范围与后续范围

首版围绕前台使用：API AI 聊天、任务、资料、栏目、图片及基础附件、导入导出与备份。账务、健康、保单、专题及生成页面等现有模块逐项接入，未验证的模块不显示为完整可用；不得丢失专门业务规则。首版是否纳入每项复杂功能由试验后的能力表确定。

Gmail、持续后台扫描、完整扫描 PDF 处理、语音、通知和跨设备自动同步分项推进。Windows 与安卓首版各自拥有本地数据；数据迁移通过明确的导入/恢复进行，不默认自动同步。跨端导入检查 schema 版本和功能兼容性，不允许旧客户端静默覆盖新结构。

## 统一验收原则

1. **独立性**：电脑服务关闭、无远端秘书服务时，安卓能启动、读写和重开数据；云端模型连接单独标注。
2. **源码共用**：从同一提交构建；一次共享规则更新同时影响网页/Windows 和安卓。平台层不重复规则；仅模拟安卓接口不算安卓验收。
3. **数据可靠性**：覆盖升级、进程结束、失败保存、附件重开与备份恢复均用合成数据验证；卸载可能删除应用数据，必须有导出路径。
4. **既有版本**：每轮改造执行对应的既有测试；涉及页面和桌面桥接时做实际浏览器/桌面回归。
5. **真实设备**：模拟器、静态构建和自动测试分别记录；至少一台安卓平板验证后才能宣布平板可用。缺设备时明确待验，不补写成功。
6. **包的边界**：保持仓库打包白名单和密钥剥离约束；只使用合成测试资料，不打包私人仓库、正式数据库、用户凭据或开发机配置。
