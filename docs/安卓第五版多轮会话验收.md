## 手工验收

1. 确认版本0.5.0、旧任务和书单保留，选择DeepSeek；若密钥仍显示已保存，无需重填。
2. 发“请记住测试暗号：蓝色星星”，等回复后再问“我刚才让你记住的暗号是什么？”；应能连续追问。仅用普通测试短语，不填写真实密码或凭据。
3. 新增一条测试待办，成功后另发“把刚才那条待办标记完成”；检查真实任务状态、原始要求保留且不重复新增。
4. 填一条未发送草稿，退出再打开，选择DeepSeek；历史与草稿应保留，可继续追问。启动默认免费离线模式，选择DeepSeek本身不会发起模型请求。
5. 新建对话后历史区/临时结果清空；切回旧对话仍能看到历史。新对话不带旧上下文，但操作同一本机任务和书单。
6. 请求中点取消，或切后台再回来：显示中断/未完成提示，保留草稿，不自动重发；先查询已保存结果。另用只聊天的请求测试强停重开：应标记中断，不自动连接模型。
7. 免费离线演练、书单和待办手工操作继续可用；离线演练的对话历史与DeepSeek隔离。

## 实现与共用边界

- 直接使用未修改的Pi agent-core 1.4.0循环和user/assistant/toolResult消息；成功历史作为上下文，不重新执行历史工具。每次重新生成当前系统说明和工具声明，不保存历史系统提示词。
- 纯模块 `src/lib/pi/conversation.mjs` 定义版本化快照、轮次状态、草稿、恢复与上下文投影，纳入共享依赖检查。当前由安卓使用；正式网页/Windows仍用Pi SDK SessionManager，**没有统一两端会话存储或支持文件互导**。
- 正式运行层的保守上下文估算原样提取至 `context-budget.mjs`，Node与安卓均调用。正式SDK的自动压缩不变；安卓尚未接自动压缩，过长时拒绝发送并保留历史，不静默截断。
- SQLite适配器负责快照事务与版本比较。发送前先保存轮次，每次Pi完整消息结束后再保存；保存故障或冲突时停止发送，保留输入和旧快照。
- 重开将running轮次标为interrupted，不恢复网络请求。下一轮只带该中断请求及明确核对提示，不带缺少配对结果的残缺工具调用；已提交业务结果和回执仍保留。

试验限制：每种模式最多20个对话，每个最多40轮，快照最多240000字符；没有会话删除/导出，达到限制时拒绝新增且保留已有数据。重开按最近保存时间加载，不保证恢复上次仅浏览而未保存的对话选择。每轮最多4次模型请求/8次工具操作，请求仍受60000字符限制。当前对话历史会发送到DeepSeek，增加输入和费用，界面已说明。

未完成：完整Pi coding-agent会话移植、安卓自动压缩、最终共用React界面、任务专属模式、附件、会话跨端导入与同步。本版仍为可替换的链路验收界面。
