## 手工验收

1. 顶部显示 0.4.0、“我的平板秘书”，原书单仍在。
2. 手工创建一条待办，填写原始要求和截止日期；列表应显示原文、正确日期、默认“待办/其他/中优先级”。
3. 点“标记完成”，默认未完成列表不再显示；切换“已完成”后仍能看到原始要求和日期，重开应用后保持。
4. 默认离线演练现在创建一条“安卓待办演练”，再查询确认；一次点击只新增一条任务，不会新增书单。没有调用 AI，不收费。
5. 选择 DeepSeek，若显示已保存密钥，无需重新填写；请求“新增待办：预约牙科检查，原始要求是先确认时间再预约，截止日期 2026-11-09”。确认真实任务出现在列表，检查要求和日期。
6. 再请求“把预约牙科检查标记为完成”，应先查询真实 ID 再修改；切换到“已完成”确认原要求未被这次状态更新覆盖。
7. 原书单新增/编辑继续可用；页面规则检查现在为十项。

真实模型仍按服务商规则计费，发送内容包括本轮请求、前25条书单以及工具查询的任务/记录。当前每轮独立，最多4次模型请求、8次工具执行；任务查询默认未完成、20条，上限50条。手工列表最多50条；本试验存储最多2000条任务，不是正式平台的新配额。

## 共用代码与保留的边界

- `src/lib/tasks/contracts.ts` 抽取正式通用对话已有的 createTask/listTasks/updateTask 参数、说明和状态/分类枚举；网页/Windows 的 `agent-tools.ts` 与安卓直接引用。
- `src/lib/tasks/policy.ts` 共用创建默认值、原文保存、负责人规范化、日期转换、局部更新、默认查询条件与公开 DTO。正式执行仍走原 Prisma 及现有审计/事务入口。
- 不将待办作为自定义书单记录存储：安卓使用独立任务表；Java 仅承担 SQLite 投影、查询、版本条件更新与原子回执。模型写任务也使用同一 `tool_receipts` 事务机制。
- 通用对话原有规则保持：未提供字段不覆盖；空负责人取消指派；未填写期限不推断日期；更新的空日期字符串沿用原来的不变更语义。未新增统一的严格日历解析；任务专属对话的日期/范围/原要求保护仍由原 `task-chat-scope.mjs` 执行，未被放宽。
- 本轮没有迁移任务专属对话、前后置任务、专题、附件、家庭成员配置、提醒与通知、完整持久会话、同步或最终共用 React UI。当前静态页面是可替换的链路验收界面。
