# 安卓语音对话实施计划

目标：在手机本地应用中使用语音与现有 Agent 交谈，并尽量与网页和 Windows 共用语音界面、音频处理及业务规则。安卓保留必要的系统权限、密钥存储和网络适配。先完成轮流语音，再推进阿里云实时语音；每个阶段分别验证，不能以构建通过代替真机验收。

## 第一阶段：轮流语音对话

1. 抽离网页连续语音对话对 ASR、TTS 服务的调用边界，保留原有网页行为，让安卓可以注入平台服务。复用原有语音检测、WAV 编码、朗读文本处理和聊天 Agent。
2. 安卓实现麦克风权限与生命周期、语音服务配置及加密密钥存储、受限云端连接和取消机制。密钥不进入网页、安装包或 Git；服务地址及音频下载受限，退出或切后台释放录音和播放。
3. 在主对话接入共享语音界面与现有 Agent，保证识别、提交、持久化、朗读及恢复聆听；草稿不丢失，不自动重发已提交的业务操作。随后接入任务专属对话，保留任务范围与归档限制。
4. 自动化验证权限拒绝、取消、空识别、服务失败、重复请求、切后台、草稿和已有数据。打包独立版本，手机覆盖安装并验证真实麦克风、扬声器、耳机、多轮对话及创建待办。

轮流模式在识别、等待和朗读期间暂停收音，暂不支持插话；识别与朗读需阿里云配置，可能产生费用。仅在用户开启后收音，安静时不上传音频。

## 第二阶段：实时语音对话

1. 梳理网页现有实时协议、音频播放、打断和任务回执，抽出跨平台可复用部分；设计安卓安全连接与本地持久化适配，不直接依赖网页的 Node 进程。
2. 接入实时音频、打断、网络异常与生命周期管理，连接现有 Agent 和任务范围；确保任务去重、执行结果可靠呈现，不因重连重复执行。
3. 自动验证音频顺序、打断、错误及数据保护；再用独立测试数据进行真实服务和手机验收，检查长时间使用、扬声器回声和后台退出。

实时模式开启期间会持续向服务商发送麦克风音频，需在界面说明；服务需独立配置并可能计费。
