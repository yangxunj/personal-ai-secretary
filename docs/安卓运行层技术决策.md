# 安卓运行层技术决策

日期：2026-11-03。状态：选择 WebView + 平台存储适配作为首个隔离试验；正式产品框架在设备验收后确认。

## 决定与原因

先将现有栏目校验源码构建为浏览器 JS，在 Android WebView 中直接执行；安卓 SQLite 适配器只处理持久化，不复制字段规则。主应用继续使用原来的 Next.js/Prisma 路径，两边引用同一规则文件。

首包采用原生 Java Activity、AndroidX WebViewAssetLoader 与 SQLiteOpenHelper，减少未知依赖；没有引入自写 AI 编排、完整原生业务 UI 或远程秘书服务。试验的简单 HTML 页面用于检验数据链路；正式版本仍以共用 React 界面与应用服务为目标，不能把试验页面演变成另一套独立产品。

没有修改主应用依赖或数据库，新增工程位于 `experiments/android-shared/`。本轮主张仅为“现有纯规则可在安卓网页资源中构建，并可调用本地适配器”；真正 WebView 执行及 SQLite 持久化仍待设备结果。

## 内嵌 Node 候选的处理

Node.js Mobile 能将 Node 嵌入移动应用，但这不自动解决 Prisma、图片原生模块、Pi SDK 和生命周期兼容性。

- Prisma 官方系统要求列出 Windows、macOS、Linux 及 glibc/musl 条件，没有将 Android/Bionic 列为支持平台。此事实不证明所有替代引擎方案都不可能，但不足以支持“把现有 Prisma 直接打进去”。
- 当前安装的 Pi coding-agent 1.4.0 声明 Node `>=22.19.0`，依赖进程、文件会话及其他 CLI 组件。公开 Node.js Mobile 仓库读取到的源码记录包含 Node 18.20.4 更新，未核实出能承载本项目完整依赖链的现成受维护组合。未据此声称所有 Node.js Mobile 分支均只支持 Node 18。
- 本轮不投入完整原生引擎移植，以免为保留桌面运行时形成长期维护分叉。该候选按“缺乏可直接采用的兼容证据”退出本轮，没有伪造 Android 上的失败运行结果。

Pi 未来如何复用会话与工具循环仍是明确待解决项：应评估 SDK 的可移植部分及存储/网络抽象，保持工具契约、权限、审计、压缩和去重语义；不能用另写的简单聊天循环当作已完成 Pi 迁移。

## WebView 的边界

- 使用官方 `WebViewAssetLoader` 的 HTTPS 本地来源加载打包资源，禁用 file/content 访问与混合内容。
- 仅允许本地固定来源和 `/assets/`，其余导航与请求拒绝；CSP 禁止网络、iframe、对象和内联脚本。本包也不声明 INTERNET 权限。
- JavaScript bridge 只提供记录追加与读取，不提供任意 SQL、文件路径、shell 或密钥读取。业务规则由可信打包 JS 调用，然后才写入平台存储；原生桥接不接受远程/生成页面内容。
- 正式产品接入 AI、生成页面和附件时，需要重新设计网络、异步桥接与隔离来源；不得把当前受信任桥接直接暴露给生成 HTML。

## 固定版本与复现

Gradle 8.9 / AGP 8.5.2 / JDK 17 / SDK 34；WebKit 1.11.0；设备测试 runner 1.6.2、ext-junit 1.2.1。官方 AGP 8.5 要求至少 Gradle 8.7/JDK 17，支持的最大 API 为 34；本组合已实际构建通过。首次补齐 Google Maven/Maven Central 依赖后，离线构建也成功。

共享规则使用主仓库锁定的 Zod 和 TypeScript，打包器复用已安装 Next 附带的 webpack，未安装另一套前端依赖。该路径是试验期的复用方式；正式工程应显式管理打包工具版本，不能假设所有未来 Next 版本保留私有编译入口。
