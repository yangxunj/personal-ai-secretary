# 安卓首阶段实施计划

日期：2026-11-03。对应 [多端共用路线](安卓与多端共用路线.md) 的 M0～M2。

## 本阶段目标

用最小真实链路回答三个问题：现有代码能在安卓复用到哪一层；安卓能否独立持久化并恢复；同一业务规则更新后网页/Windows 和安卓是否同时获得变化。

试验位于 `experiments/android-shared/`，正式用户数据与发布包不参与。M0 只盘点；M1 才添加安卓工程及必要依赖。先复用现有纯规则，不提前重构全部页面或替换正式数据库。

## 步骤与验收

### P0：建立源码与环境基线

- [x] 确认当前代码 `5657662`、工作区原先无修改、远程 `origin` 与当前 `main`。
- [x] 阅读 Windows 启动、Next 配置、Prisma 数据源、Pi 会话、栏目规则/服务和 Server Actions。
- [x] 检查本机工具文件：Node v24.19.0、Java 17.0.20.1、Android SDK platform android-34、build-tools 34.0.0、platform-tools 37.0.1；存在 Gradle 8.9 缓存。缓存存在不代表 Gradle 构建成功。
- [x] 运行静态依赖盘点并将结果记入 [试验说明](../experiments/android-shared/README.md)。报告仅列代码路径及依赖名，不读取 `.env`、数据目录或凭据。
- [x] 核实 SDK/Gradle/Android 插件组合并完成构建；补齐官方 WebKit/设备测试依赖后，离线构建通过。ADB 已检查，无已连接设备；用户选择接收 APK 手工安装。

### P1：确定两个候选方案的验证边界

- 方案 A：安卓容器内嵌 Node 兼容运行层。验证 Next 最小路由、Prisma 查询、Pi 会话持久化及所需原生依赖的真实可用性；不能仅以 Node hello world 作为通过证据。若缺乏可维护路径，记录阻塞并结束该候选，不无限修补。
- 方案 B：Android WebView + 共享 JavaScript/TypeScript 核心 + 安卓存储/文件桥接。验证共享规则在 WebView 直接执行、本地 SQLite 事务、应用私有附件目录与流式模型连接；评估 Pi 的 Node 依赖如何保留共享编排或进行适配。
- 按可维护性、共用边界、开发/发布工具成熟度、生命周期、升级和包体决定正式方案。选择框架前查当前官方资料；当前计划未把任何框架或第三方运行时标记为已兼容。

交付：`experiments/android-shared/` 中的可复现步骤、实际通过/失败记录，以及路线决策文档。选定方案后再锁定版本与许可清单。

### P2：先验证一条确定的共享规则

优先使用现有 `src/lib/collections/schema.ts` 中的栏目定义/记录校验，当前文件只有 Zod 运行依赖和 i18n 类型依赖；其业务规则已被现有服务调用，适合作为小切口。先直接引用同一源码，不复制校验实现。

用合成“平板书单”验证：创建定义、合法记录保存、必填/日期/选项错误拒绝。Web/Windows 路径和安卓路径都必须使用这份规则；安卓适配器只负责数据操作。验证一项真实共同规则变化的传播，可在隔离分支/试验提交演示，验收后还原演示改动，不为演示改变正式产品规则。

补充任务应用服务后，再连接 AI“创建待办”：模型工具调用 → 共享服务 → 本地事务 → 界面显示。不能让 AI 与手工操作各写一份校验。工具的审计、去重、任务权限与更新冲突语义应保留。

### P3：安卓本地闭环

1. 安装开发 APK，应用不配置电脑或远端秘书服务地址。
2. 创建记录，退出再打开仍在；结束应用进程再打开仍在。
3. 开启飞行模式仍可启动、查询和手工编辑；AI 调用明确显示网络错误，保留草稿。
4. 使用确定性模型替身验证工具流、取消和重试，再在具备授权及配置时做真实 API 验证。替身通过不计为真实模型通过，不擅自调用现有用户付费密钥。
5. 在平板前台连接模型并通过 AI 创建待办，确认持久化与 UI 读取同一记录。
6. 用第二个开发包覆盖安装，确认原记录/附件与 schema 升级正常；失败时保留原始数据。

### P4：共用更新与旧端回归

- 从同一源码提交构建网页/Windows 与安卓；记录提交号和构建版本。
- 对共享校验或任务规则执行同一组业务输入，并在实际安卓环境验证规则生效。
- 网页真实交互验证原功能；涉及 Windows 启动或桥接时验证桌面。开发浏览器预览不能替代 Windows 包验收。
- 跑与改动相符的既有栏目、AI 工具及类型检查；涉及主应用接线时执行生产构建。按风险补充边界测试，不为纯文档改动跑整套产品测试。
- 审查依赖方向，禁止安卓目录复制提示词、字段规则或另起一套数据语义。对共享核心建立禁止导入框架/系统模块的检查。

## 本阶段退出条件

M0 完成：盘点可重跑、风险和环境状态清晰。M1 完成：至少安卓测试设备可运行本地闭环，选定路线并记录取舍。M2 完成：共享真实规则已接两端并通过更新传播验证，且既有功能回归通过。

若只有浏览器或模拟器证据，保持实机待验；若缺下载权限或设备，不把阶段标为完成。将环境准备、运行兼容性、业务正确性和产品验收分别报告。
