日期：2026-10-27。代码基线：`412268952ad5fbc75a714766b9e7c1abff592c4e`。

本文是后续施工与验收入口。[早期对齐分析](AI对话功能对齐与接口演进计划.md)保留比较依据，[Pi 试点记录](Pi内置Harness架构与试点.md)保留已完成实现及证据。不能把早期未完成清单照单重做，也不能把私人版的通过结果视为开源版已验收。

当前进度：M1A（Pi 搜索及执行边界）、M1B（Codex 搜索及旧线程连续性）、M2A（共用附件工具与完整文字续读）已完成代码和相应验收。下一阶段 M2B 处理轻量业务上下文、业务原文续读与历史查询增强。两个搜索开关均默认关闭，尚未发布包含这些改动的新安装包。

## 为什么需要再写实施计划

之前已确定方向，但当前代码已经发生变化：Pi 已负责压缩与上下文持久化，执行回执也与 Codex 共用；文件工具、引用和工具注册仍有后端差异。需要把“吸收私人版经验”落实到依赖顺序、可交付里程碑和失败恢复策略，避免同时改工具协议、历史会话和桌面依赖后难以定位回归。

## 已确定的架构边界

- Codex 与 Pi 管理各自模型上下文、会话和压缩；平台保存完整产品记录、业务权限、文件原件、可核验引用及执行审计。暂不删除旧 API 自建路径，也不为所有后端统一套用旧压缩。
- 已有对话保留后端、Codex thread 和 Pi session，不静默重建或迁移。默认后端改变仍只影响新对话。
- 查询权限、工具可用范围与写入授权分开：跨任务只读能力不扩大写权限；文件使用平台附件 ID，不开放任意磁盘或 shell。
- 不改私人版，不导入私人数据或凭据；参考其公开可复用的策略，重新在开源版验证。
- 网络搜索结果、附件和历史留言都是数据，不能作为新指令或写入授权。

## 里程碑与顺序

### M1A：只读执行边界与 Pi 公开网络搜索（本轮首个交付）

交付范围：

1. 使用可信工具定义上的标记区分耗时只读工具；模型不能用参数或工具名字自行绕过写事务。文件读取和网络读取使用外部只读路径。
2. 只读工具仍先保存 running 审计，成功保存结果，失败/取消记 failed；同 call ID 返回已完成结果，不重新联网。重启后未完成回执保持失败，不自动重复请求。
3. Pi 增加 `webSearch`、`fetchWebPage`。不改变 Chat Completions 协议，不假设 Flash 会自行进行服务端搜索。
4. 设置页提供默认关闭的 Pi 搜索开关及专用 DeepSeek key；仅 DeepSeek 官方聊天地址可复用其聊天 key。其他服务商 key 不能发送给 DeepSeek。密钥只在服务端读取，页面仅显示是否可用。
5. 固定 DeepSeek HTTPS 服务地址，不在本机访问模型指定网页；不跟随服务重定向；总计最多 6 次请求/轮、单次 25 秒、响应最多 2 MiB，无自动重试。搜索最多 5 条；网页结果最多 24K 字并显式标记截断。
6. 搜索摘要与读取网页区分来源类型；仅本轮成功工具返回的 token 转为可点击来源，不复用历史 token。文件引用保持原件哈希核验。来源核验代表工具确实返回了该来源，不代表网页事实必然正确。
7. 关闭搜索后下一轮不注册网络工具，包括已有 Pi session；不清除会话记忆。

改动地图：`agent-turns.ts`、`agent-tool-policy.ts`、`pi/files.ts`、`pi/chat.ts`、`pi/runtime.mjs`、`web-search/*`、设置页/服务端 action/英文词典、隔离测试。

验收：真实 SQL 证明外部读取等待期间数据库可写；业务事务仍可取消回滚；网络端点/密钥隔离/预算/大小/超时/取消/错误脱敏；实际 Pi SDK 工具循环、来源转换和旧 session 开关刷新；实际聊天路由及独立 Electron Node standalone 回归。使用合成数据，真实供应商请求另列证据。

明确限制：本轮开关只控制 Pi；原 API 的百炼原生搜索仍按原逻辑。搜索词/URL 由模型形成，最小披露约束属于提示和用户操作规范，尚无能够保证识别所有个人信息的出站 DLP。网页超长正文暂不支持续读。

### M1B：Codex 公开网络搜索与旧线程连续性

先完成受限搜索，不与资料工具升级绑在一起：

- 对照私人版 `e3655ddb27b4f728986ba1c14bab03855406aa0b`，复核本机 app-server 版本、原生搜索工具及配置，不把单个 `web_search=live` 当成已经可搜。
- 搜索仅允许限定的搜索 connector；apps 默认 deny，禁继承其他 apps/MCP；shell、插件、浏览器和电脑操作继续禁用。启动及 thread start/resume 配置保持一致；临时标题/页面客户端保持默认禁搜索。
- 网络策略可在每轮覆盖；新旧通用、任务 thread 分别验收随机口令保留及实际搜索事件。不能为启用搜索静默重建 thread。
- 从本轮成功原生结果采集网页来源；处理分段原生引用，未知来源明示未核实。与平台文件引用分开，记录调用次数，不新增完整搜索词日志。

完成标准：四类新旧对话均产生真实原生搜索结果、可打开来源并保持既有记忆；关闭后无搜索工具；确认未开放无关 connector。不能只依赖模拟协议测试。

### M2：共用资料工具、轻量上下文与完整续读

依赖 M1 的执行分类和来源机制，按可独立验证的逻辑逐项推进：

1. 把 Pi 文件/历史工具和来源转换提取到共用模块，保持工具名称与旧 Pi session 兼容。Codex 先检查当前 app-server 能否安全刷新旧 thread 的 dynamicTools；不支持时提供明确新会话入口，保留旧 thread 继续聊天，不能假装旧工具已更新。
2. Codex 提前归档上传附件并创建有明确失败状态的助手消息，使工具可按已归档 ID 读取和生成文件；确认去重分类不复制附件。
3. 任务每轮只注入轻量快照与版本、资料目录、读取入口，去掉重复准备。先提供原文续读工具，再削减注入内容，避免失去信息。
4. 对任务 detail/result、文档、专题、留言和附件提供长度/版本/定位、`nextOffset=null` 的结束协议。续读使用预期版本，变动时要求从头重读，不能混合新旧版本。
5. 移除 DOCX/XLSX 工具读取前的固定截断或提供单独完整解析模式；上传预览限长可保留。先验证大于 40K 的尾部随机标记，再报告完整续读已完成。
6. 历史查询支持时间/关键词、稳定游标和单条正文续读；明确读取范围与历史内容不构成授权。业务来源引用区分需求、执行进展、留言和附件，不用留言概括替代原件证据。
7. 回复规则强调先查现有资料，再问确实缺失的问题；读取与保存的完成状态以工具回执为准。

完成标准：Codex/Pi 同一合成资料获得相同定位和原文证据；任务范围拒绝越界；旧会话可恢复；大文件/长留言可抵达末尾；版本变化拒绝混读；引用可点击且不接受伪造/历史 token。

### M3：文件图文、页面与桌面依赖

- Word 增加结构、图片、批注/修订、页眉页脚/脚注定位；PDF 指定页、裁剪与表格；图片作为真实多模态内容传入两个运行时。
- 增强解析、缓存按原件哈希与解析版本失效；控制文件大小、页数、像素和工具输出，不以文本截断掩盖遗漏。
- 可选依赖不随安装包隐式假设：明确系统支持、安装检测和纯文字降级；隔离 Electron standalone 禁止从源码 node_modules 借用依赖。
- 不覆盖原件；生成文件仍只写平台交付区。Excel 原有业务工具及写入回执保留。

完成标准：固定含图/批注/修订 Word 与扫描 PDF 样例可精确定位，内容与页面核对；无可选依赖时给出准确降级；安装包运行成功与源代码构建分别记录。

### M4：按需检索与交互性能

- 先完整读取，再引入可选增量语义索引。相似命中仅提供候选，结论回原文；删除、改版、权限改变时索引同步失效。
- 跨事项查询只扩展明确的只读范围，不扩大任务写权限；索引原文/摘要外传须有明确配置。
- 长聊天增量加载、消息渲染与标题更新单独测量；标题任务不继承工具、网络或业务写权限。
