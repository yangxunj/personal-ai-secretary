# 文档结构与图像读取

2026-10-27，M3 源码能力。尚未随新安装包发布；安装、升级及完整桌面界面验收与独立 Electron Node standalone 分开记录。

## 使用

Pi 对话和工具档案第 3 版起的新建 Codex 对话，可以按平台附件 ID 回读已保存的文件，无需为读取历史图片或扫描页重新上传。任务对话只访问当前任务/当前会话的附件，通用对话沿用现有附件范围；没有开放磁盘路径或 shell。

- Word：查看段落、表格/行/单元格标记、插入/删除/移动修订、批注引用及正文、页眉页脚、脚注/尾注；按部件续读完整文字，读取部件中引用的嵌入位图。支持 DrawingML 和旧 VML 图片引用。格式/表格属性修订显示标记，不重建版式。
- PDF：任意指定页（包括未随上传展开的后续扫描页），读取文字坐标或页图；可指定归一化裁剪区观察表格、图表和扫描文字。旋转先应用，裁剪坐标以显示后的左上角为原点。
- 图片：回读已归档 PNG、JPEG、WebP、静态 GIF，可裁剪。动画/多帧图明确拒绝，避免把一帧误当完整内容。

看图需要所选模型支持图像。DeepSeek Flash 的现有配置属于纯文字模型，可读 Word 结构和 PDF 文字层，不能通过这些工具识别扫描文字；需要看图时选择视觉模型并按已有会话配置规则新建对话。平台不会另选模型或暗中调用 OCR 服务。

旧 Codex 第 0/1/2 版线程保留原工具与记忆，界面给出新建对话入口，不静默升级或重建。Pi 继续原 session，每轮更新工具。

## 工具与证据

| 工具 | 用法 |
| --- | --- |
| `inspectAttachment` | Word 部件/嵌图元数据列表，每页 20 项；PDF 总页数；当前模型和渲染依赖可用性 |
| `readDocumentPart` | Word 部件 ID，例如 `word/comments.xml`；PDF `page:8` 输出带坐标文字。最多 6,000 UTF-16 单位，按 `nextOffset` 续读 |
| `readAttachmentVisual` | 原图片；PDF `page`；Word `imageId`。可选 `crop={x,y,width,height}`，各值归一化，必须落在图像内 |

先检查附件，再用返回的 `version` 读取部件/图像。以上三个工具共用 `rich-v1` 版本；与原 `readAttachment` 的 `text-v2` 版本不同，不能混用。文字续读、元数据续页必须携带版本。按原件字节与解析协议标识计算版本；每次先核对当前权限和原件，回复保存前再核验引用。更换、删除、解绑的来源不能沿用旧证据。

图像通过 Codex `inputImage` 或 Pi `image` 内容块发送，不把 base64 放进文字消息。聊天界面事件仅包含尺寸/类型/大小元数据；为确定性工具重放，受限图像内容保存在 SQL 工具审计和原生 harness 会话中，随原有数据备份处理。内存解析缓存按版本和读取参数区分，最多 8 项/16 MiB；不在磁盘另存私有解析缓存或覆盖原附件。

引用打开原附件，PDF 带页码；Word 部件、文字起点、图片 ID、裁剪范围写在来源标签中。它不是永久原文快照，也不是 Word 单段高亮预览页。

## 支持边界与资源上限

- Word 读取的是 OOXML 结构，不能当成 Word 排版页码。标注修订，不自动接受修订；不执行宏、字段、嵌入对象或外链。图表/SmartArt/复杂排版和未支持的嵌入内容需要导出 PDF 再观察；不宣称支持所有 Office 结构。PDF 文字坐标不等于已准确恢复表格单元格，表格可用页图/裁剪交给视觉模型核对。
- 工具读取原件最多 25 MiB；Word 最多 1,000 个 ZIP 条目、1,000 个部件/图片引用组合，条目名 200 字符、可读部件 ID 150 字符、关系 ID 100 字符、关系目标 1,000 字符。单 XML 4 MiB、XML/关系文件合计 16 MiB、单嵌图解压 10 MiB、单部件结构文字 200 万字符，限制 XML 节点及深度。拒绝 DTD/实体声明；逐块限制解压大小，超限明确失败，不伪装成原文结束。
- PDF 最多 1,000 页；输入位图最多 2,000 万像素。输出图像最长边 2,200px、PNG 最多 2 MiB、每轮最多 6 次图像读取尝试。PDF.js 可能忽略超过像素限制的内嵌图片，工具会说明该限制；空白区域不能被当成“原件没有内容”的证据。裁剪不等于无限放大，模型仍可能看不清细字。
- Word 结构依赖纯 JS 的 JSZip/xmldom；位图处理依赖 sharp，PDF 渲染额外依赖 `@napi-rs/canvas` 的本机二进制。`inspectAttachment` 检测可用性；缺少支持时返回 `renderer_unavailable`，保留文字/结构工具。当前实际验收平台为 Windows x64；其他系统不能据此宣称已验收。

## 验证入口

```bash
node --test scripts/*.test.mjs
node scripts/pi-integration.mjs --build --electron --media
node scripts/codex-search-integration.mjs --live --standalone --electron --media
```

集成使用独立 SQLite、上传目录和 `.next-pi-qa`，不覆盖正式 `.next`。已有隔离构建用 `--standalone`；没有时用 `--build`。Codex 显式 `--live` 使用本机登录额度，只发送合成资料，创建的测试线程结束后归档。Pi `--media` 使用合成视觉接口核验 SDK/原生图像传输，不冒充真实模型识图；真实识图由 Codex 测试的图片内随机码证明。详细回执及剩余验收见 [实施计划](对话能力改造实施计划.md)。
