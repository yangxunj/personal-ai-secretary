# DSH 侧边栏替换探针（仅隔离研究）

这个目录记录失败边界，不是可交付插件。不要安装到日常使用的 DSH，也不要在有真实数据的配置中运行。`0.0.4` 会使自定义侧栏抛错，DSH 回退到默认侧栏；不能据此认为替换已经完成。

## 已验证的现象

使用 DSH 桌面版 0.2.2-rc.2 自带运行时，分别在全新隔离 DSH_HOME 的 Web 实例中安装探针并观察实际界面：

1. 禁用 `ui-sidebar`，由探针声明其子插槽并占据 `sidebar`：自定义单列侧栏、原生对话、插件页面和账号入口能出现；但工作区和会话列表没有出现。至少工作区组件的客户端清单依赖原 `dsh-client-ui-sidebar`，因此不能通过简单禁用原组件保证其他功能正常。
2. 保留 `ui-sidebar`，探针也声明同名子插槽：启动失败，提示 `sidebar.panellist` 已声明。子插槽不能同时由两个侧栏声明。
3. 保留 `ui-sidebar`，探针不声明子插槽且与其使用相同优先级：启动失败，提示 `sidebar` 同优先级已注册，并提示使用不同优先级（数字越小越优先）。
4. 本目录版本使用 `priority: -1` 且不声明子插槽：可以启动，但探针不能获得 `renderSlot`，调用时报 `renderSlot is not a function`，DSH 将失败侧栏回退为原侧栏。原生会话列表仍在，说明回退生效；不是替换成功。

这些结果只说明所试方法和当前版本的行为，不排除其他受支持的扩展方式。没有在真实桌面窗口或用户数据上试验，也没有验证实际模型对话、移动端、升级兼容或无障碍行为。

## 复现

使用独立的临时 DSH_HOME 和 AGENTS_HOME，先确认没有指向用户数据目录，再将此目录 `npm pack` 后安装到该隔离配置并启动 DSH Web。浏览器控制台可观察侧栏报错和回退。探针不得作为常规插件分发。

## 后续方向

继续研究如何在维持会话、设置和动态插件入口依赖的同时替换整个侧栏，例如独立构建或替换 DSH 的侧栏组件；需要先确认依赖、许可证、升级和回退机制，做隔离原型并完整验证，再决定是否提供安装包。不要以隐藏或模拟界面的方式宣称已经完成统一。
